## 第三轮：配色与可读性专项（用户要求"每张图都要检验配色"）

`scripts/verify_figure_layout.mjs` 从纯版式扩展为**版式 + 配色**双检，新增三项：

| 检查项 | 判据 | 结果 |
|---|---|---|
| 文字对比度 | 文字色 vs 其所在形状底色，正文 ≥4.5:1、大字 ≥3:1（WCAG AA） | 13/13 通过 |
| 配色数量 | 新图 ≤4 种彩色；既有图 ≤6 种（排除近黑文字墨色与近白底纹） | 13/13 通过 |
| 灰度可分辨性 | 任意两种彩色转灰度后亮度差 ≥0.05（黑白打印不混色） | 13/13 通过 |

**修掉的一处真实配色缺陷**：`water_layout.png`（申报书图 1）原有 4 个语义色中，
受限元件描边 `#826521` 与泄漏路径描边 `#a26437` 的灰度亮度仅差 0.02，
蓝色 `#42657b` 与负载绿 `#526b54` 仅差 0.011 —— **黑白打印时这三对会混成同一层灰**。
改法（只改描边色，不动几何与文字）：
- 负载绿 `#526b54` → `#6f8a72`（提亮）；
- 受限黄 `#826521` → `#c9a227`（金黄）；
- 泄漏路径 `#a26437` → `#4a4a4a`（中性深灰，靠浅色填充 `#faede2` 区分）。
改后 3 个彩色灰度亮度 0.119 / 0.228 / 0.384，两两差 ≥0.10。
同步修了 `build_application_design_figures.py::render()`：pymupdf 缺失时不再硬崩
（跳过 PDF 回执校验，版式校验统一交给 `verify_figure_layout.mjs`），否则该生成器在本机跑不动。
