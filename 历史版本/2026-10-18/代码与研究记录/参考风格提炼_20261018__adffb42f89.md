## 一、章节骨架（以文件 2 为准）

文件 2 全文有效字符约 2.38 万，按一级标题的篇幅占比：

| 章节 | 占比 | 二级标题 |
|---|---|---|
| 封面 / 成员表 / 导师信息 | ~7% | — |
| 一、项目简介（300 字左右） | 2.3% | — |
| 二、申请理由 | 3.8% | 1. 研究目的和意义；2. 已具备的基础（团队成员 / 专业理论知识 / 兴趣 / 协作精神） |

| 四、国内外研究现状和发展动态 | 22.0% | 1. 国内现状（3 个主题小节）／ 2. 国外现状（3 个主题小节）／ 3. 发展动态与趋势（3 条，每条"从 A 到 B"句式）／ 4. 现存问题（3 条）／ 5. 本项目的切入点（3 条，与 4 一一对应） |
| 五、特色与创新点 | 12.9% | 1. 项目特色（成段）／ 2. 创新点 2.1–2.5，每条"领域词 + 冒号 + 一句话主张"（如"技术协同创新：空地一体的动态协同作业模式"） |
| 六、预期成果 | 3.3% | 论文 / 软著 / 实用新型 / 软硬件系统套数 / 其他，各一小段 |
| 七、项目年度目标和工作内容 | 21.0% | 1. 年度目标（两大段）；2. 工作内容 2.1–2.7（硬件开发、系统集成、数据交互测试、决策模型、专利申请、农田测试、示范应用、云平台、成果总结），**每节配一张"阶段 / 实施内容 / 核心技术参数 / 验收标准"四列表** |
| 八、已有基础 | 5.0% | — |
| 九、经费使用计划 | 2.3% | — |

**结构观察**：
- 正文重心 = 方案（20%）+ 现状（22%）+ 年度工作内容（21%），三者合计 63%；简介与申请理由合计仅 6%。
- "现状 → 问题 → 切入点"三段式是它最干净的部分：每个问题有对应编号的切入点，不散打。
- 实验方案是"周期 + 阶段名（如'单模块性能标定测试（周期：1 个月）'）+ 指标表"结构，指标表固定四列：测试项目 / 计划指标 / 测试方法。
- 工作内容全部表格化并带"验收标准"列——立项书就把验收条款写死，这是值得学的。

## 二、硬件选型句式模板（提炼自文件 1，已去除其具体内容）

文件 1 的硬件章节（5.2）每个器件固定一小节"（N）XX 模块设计"，内部高度模式化。提炼出 5 个句式骨架：

**句式 A —— "采用 + 原理一句 + 量程 + 精度 + 实测修正"**
> 采用〔芯片/模块名〕，〔一句工作原理：测什么、靠什么机理〕。〔量程：X 至 Y，与〔干扰量〕无关〕。〔精度：±N%〕。但在实际使用/台架复测中发现〔与手册不符的点〕，因此〔对策〕。

适用：MDM490 差压变送器（量程档 35–40 kPa、±0.5%FS，可加"实测零漂发现…"修正句）、SGM58031 ADC。这条句式的价值在最后一句——文件 1 敢写"但实际使用中发现仅能测到电压值"这种手册没说的坑，我们应继承并升级为"实测 + 数据"。

**句式 B —— "机理链 + 输出形式 + 总误差"**
> 利用〔模块名〕测量〔物理量〕，由〔敏感元件〕与〔结构〕组成：〔物理量〕流经/作用于〔结构〕时产生〔中间信号〕，经内部〔放大/滤波/温补〕后输出〔信号形式，从〔引脚/接口〕输出〕，总误差值为 N%。

适用：SEN0549 流量计（霍尔/叶轮机理 → 脉冲频率信号 → 引用 datasheet 误差，再接我们的标定修正）。

**句式 C —— "信号链换算 + 标定点 + 灵敏度 + 公式编号"**
> 如图 N 所示，〔器件〕输出经〔ADC/定时器〕采集，按〔线性/已知关系〕换算为〔工程量〕；〔典型标定点：输入为 0 时输出为 X〕，〔灵敏度：N mV/A 之类带量纲常数〕，换算公式为（公式 N）。

适用：流量脉冲频率 → Q 的换算、SGM58031 电压 → 差压的换算。我们已有标定曲线与残差入档的安排，正文可套此句式把"标定"写成显式步骤。

**句式 D —— "优点 + 量程 + 分段误差 + 接口 + 扩展能力 + 边界提醒"**
> 采用〔传感器名〕，具有〔两条定性优点〕特点；量程〔X 至 Y〕，在〔常用子区间〕内误差 ±N；输出〔数字/模拟〕信号，采用〔接口形式〕，可〔多点/多通道扩展〕；但要注意〔失效边界：线过长 / 温度超出 / 供电波动时可能……〕，具体连接见图 N。

适用：LoRa/433 MHz 模块（"但要注意发射功率受限 10 mW e.r.p.、墙体衰减下链路预算…"）、电池与功耗预算段。最后一条"边界提醒"与文件 2 的纯吹捧形成对比，是文件 1 最值得学的防守写法。

**句式 E —— "引脚映射清单"**
> 由图 N 所示，〔器件 A〕的 GND 接〔电源地〕，VCC 接〔3.3 V/5 V〕，〔信号脚 1〕接〔MCU 引脚名（功能括注）〕，〔信号脚 2〕接〔MCU 引脚名〕……通过〔驱动/协议程序〕即可实现〔功能〕。

适用：GD32F103CBT6 + SGM58031 + SD 卡 + LoRa 模块的接线说明，可直接做成"引脚/信号/去向/备注"四列表替代成段文字（比文件 1 的流水句更易核对）。

**配套写作惯例**：每个器件一节、节内固定顺序（原理 → 参数 → 接线 → 实物/电路图 → 图题"图 5-N"）；参数只给选型用得上的那几项，不给 datasheet 全家福。

## 三、语言风格量化观察

对两份文档"成段正文"（≥40 字符）做统计：

| 指标 | 文件 1（95 段） | 文件 2（195 段） |
|---|---|---|
| 含阿拉伯数字的段落 | 100% | 100% |
| 含 %/±/≤/≥ 等指标符号 | 4% | **30%** |
| 含"预计/计划/可达/约"等前瞻词 | 3% | **15%** |
| 含"实测/发现/实际…"等事后陈述 | **8%** | 1% |
| 段均字数 | 129 | 120 |

**观察结论**：

1. **数字密度两家都拉满，但数字的"时态"完全相反**。文件 2 全篇是"预计延迟 ≤1.5 s、计划精度 ±5 g/s、预计效率提升 30%"——立项书语态，15% 的段落带前瞻软承诺，"实测"只出现 1 次（还是转述别人系统的丢包率）。文件 1 则在 5.4 节真放了实测数据（内阻表、充放电曲线），并写"本实现仅测试 200 次循环放电情况，存在较大误差"。**我们要学文件 2 的指标句密度 + 文件 1 的时态区分**：预计（计划达）、已具备（已打通/已冻结）、实测（给数据出处）三种说法严格分开，绝不混用。
2. **指标句固定搭配"主语 + 动词 + ≤/≥ + 数值 + 单位 + 条件从句"**（如文件 2："在坡度 ≤15°、地表起伏 ≤20 cm 的地形中，车队队形偏差 ≤10 cm"）。条件从句让数字可信，值得学；但它不给测量方法，我们要补"证据形式"。
3. **防御性措辞**：文件 1 有（"但在实际使用过程中发现…"、"可能影响数据传输"）；文件 2 几乎没有，只把缺点写给**别人**的系统（"丢包率约 3%–5%"），自己零缺点——评审一眼看穿。我们应学文件 1：把失效边界、未验证条件写进正文。
4. **段首承接**：文件 2 惯用"锚定句"开头——"基于此 / 目前 / 除此之外 / 如图 N 所示 / 本项目聚焦…构建…；文件 1 惯用流程词——"首先 / 接下来 / 然后 / 结束实验"。**段尾承接**：两家都以"综上所述，……具有重大（价值/意义）"收束，文件 1 还常落一句具体交付（"并发表论文一篇、申请专利一项"）。
5. **成段纪律**：两家段均 120–130 字，一段只讲一个器件/一个机制，多用"（1）（2）（3）"编号切分。

**我们要学的具体做法（5 条）**：
1. 每个硬件/功能断言绑定一个带单位、带符号（±/≤/≥）的数字，并附条件从句与证据形式，写成文件 2 式的指标句但补上文件 1 式的实测栏。
2. "预计/已具备/实测"三态用词冻结：凡未做实验的一律"预计/计划"，已跑通的一律"已 + 完成时 + 出处"。
3. 每个关键器件段末尾加一句边界提醒（什么条件下指标会退化），学文件 1 的 DS18B20 段式。
4. 段首用锚定句（"基于此 / 如图 N 所示 / 承接阶段 X 的…"），段尾用"综上所述/因此"收束到下一步或价值，不写空展望。
5. 一段一事、120–150 字成段，多器件并列时直接编号化或表格化。

- 大量实物照片（底板 3D 模型、模块特写、PID 响应曲线截图）。

**可复用的元素组合建议（供滴智卫配图，避免"只会方框 + 直线"）**：

1. **形状语义编码**（学文件 1 图 5-1 + 文件 2 图 17 的混用）：矩形 = 器件/模块，胶囊 = 物理量/传感对象（ΔP、P₁、Q），菱形 = 判据/门控（CUSUM 判决、G1–G4），椭圆 = 起止/外部角色（农户、指导教师），虚线框 = 阶段/边界。一套图内保持同一语义。
2. **边上必写标注**（学文件 2 图 18）：每条箭头写"内容 + 格式 + 频率"，如"事件帧 57 B / 1 s 提交 / 重发 0–86 s"。这正好把我们协议章节的硬数字画进图里。
3. **时序图**（学图 18 的生命线 + 消息箭头）：直接用于"先落库后 ACK + 8 次重发预算"一节，画主从两条生命线、中断区间用竖直虚线阴影标出——这是参考里没有、但我们数据最硬的一张图。
4. **判断菱形 + 是/否分支 + 回环**（学图 17）：用于门控流程图（G1–G4），"达标 → 下一阶段；不达标 → 处置线"，把技术路线的处置分支画出来。
5. **数据表图 + 实测曲线对**（学文件 1 图 5-12–5-15）：每张实验结论配"原始数据表 + 曲线"组合，图下必有一段"从图中可以看到…"的文字解读，并写明误差/局限。
6. **分层色带 + 括号标注**：信号链全景图沿用我们已有的底部色带（各段守门指标），在色带端点加括号标注对应门控编号，形成"链—段—门控"三层索引。
7. **编号牌**：器件在图上挂 BOM 编号小圆牌，与经费表对应（参考两家都没做，属于低成本加分项）。

## 五、"不要学"清单（照搬会出问题）

1. **文件 2 的"预计"轰炸与指标自相矛盾**：全篇 15% 段落是软承诺；且同一指标前后漂移——4G 延迟在简介写"预计 ≤1.5 s"、方案写"延迟 ≤50 ms"、通信测试写"目标 ≤100 ms"；通信方案一会儿 4G 一会儿蓝牙 BLE5.0；表 4 写"连续 24 小时故障率 ≤10%"（过松）与"重合度 ≥98%/≥95%"（不一致）。**照搬这种"指标各处一个数"的写法会被评审当场抓住**。我们的数值口径统一清单必须继续执行。
2. **不可检验的宏观承诺**："预计 2026 年在欧美规模化推广""全产业链产值超 10 亿元""秸秆焚烧污染减少 100%"。大创尺度内写这种话是负分。承诺必须落到自己 18 个月能交付的证据上。
3. **只列器件参数、不做误差合成**：文件 1 每个器件给一个单独误差（±1%、1.5%、±2℃），从不合成到系统级；文件 2 干脆只给"1TOPS 算力"这类卖点参数。我们的"合成不确定度 U ≤ 0.20 kPa"是两者都没有的东西，**不能在重写时退回"罗列参数"的写法**。
4. **术语与拼写事故**：文件 1 图 5-1 把主控"32 单片机"画进菱形判断框（语义错误）、正文"ESP8226"（应为 ESP8266）、"仅能测量测量到电压值"（改稿残留）；文件 2 "Androrad"、"统畴"。交付前必须通读一遍专有名词与残留句。
5. **文件 1 的空展望段**：4.4 结尾两段"未来的研究方向将包括……更智能、更自动化的充电系统"与本项目无关，是凑字。段尾收束要落在本项目的下一步，不写行业愿景。
6. **文件 2 的图片卫生问题**：15 MB 文件里单张手机随手拍 2.7–3.5 MB 未压缩、未裁剪；"300 字左右"的简介写了约 500 字。图片统一压缩裁剪、字数约束严格遵守。
7. **文件 2 现状综述的"文献无出处"**：满篇"中国农业大学开发的…使衔接时间缩短 40%"但不给文献编号。我们的现状综述每条断言必须挂可检索出处（已有文献定位文档打底）。
8. **流程图语义误用**：不要把"控制器/模块"画成菱形（菱形只留给判断），不要让箭头无标注跨层跳跃——参考两家都犯过至少其一。

## 六、`docs/技术路线_20261017.md` 已具备的优点（重写时保留，勿丢）

对照两份参考，现有技术路线文档**已经超过**它们的地方：

1. **风险驱动叙事**："五个阶段各消除一个技术风险，门控通过才进下一步"——比两份参考的"背景→方案→成果"清单式组织强一档，是全文骨架，重写时保留。
2. **三态用语已经分清**："已确立/已打通/已开发完成"（起点盘点表、SD 卡链路）vs"预计/拟投"（论文期刊）vs 实测口径（"60 秒中断对照中事件缺失由 53 条降为零"）——这正是文件 2 最缺的时态纪律。
