# 一、现场与场景

## 1.1 这一步要解决什么

把研究对象落到**真实的一块地、一根管、一个人**上，并划清项目边界。

## 1.2 做法

### （1）场景落在支管上

南疆棉田膜下滴灌管网分三层：**干管 → 支管 → 毛管（滴灌带）**。本项目监测的是**支管**——它是干管到田间的分配环节，也是"一处故障影响一片地"的关键位置。

### （2）用本地实测数据锚定场景

塔里木大学所在的**一师阿拉尔市，已建成田间自动化控制灌溉 25 万亩**（[兵团胡杨网](http://m.huyangnet.cn/content/2026-07/06/content_2054202.html)）：

| 项 | 实测值 |
|---|---|
| 轮灌周期 | **72 小时**完成一轮全覆盖（十二团 3800 亩） |
| 单轮能力 | 八团 4 小时一轮，灌 110 亩 |
| **单次灌水时长** | **0.4—1.8 小时**（按 27.5—52.8 亩/小时换算） |
| 节水 / 节电 / 增产 | 30—50 m³/亩、约 5 元/亩、30—50 kg/亩 |
| 田间已有设备 | 苗情监测仪、表型监测仪、**毛管水力监测仪**；三重过滤 |

### （3）场景带来一个关键认识

> **一条支管在一天 24 小时里，只有 1—4 小时"正在灌水"，其余时间流量为零。**

这一条决定了整个项目的设计：

| 项 | 数值 |
|---|---|
| 判据确认门限 | 15 秒 |
| 灌水窗口 | 0.4—1.8 小时 = 1440—6480 秒 |
| **门限占窗口比例** | **0.2%—1.0%** |

**⇒ 门限不是瓶颈；"早期"的正确口径是"第几次灌水发现"，不是"第几秒"。**

### （4）政策依据

《加快农业农村现代化"十五五"规划》两处直接对应：
- **"加强新疆优质棉花生产"**（二·一）
- **"推进人工智能运用和智慧农业发展"**（四·十四）

### （5）项目边界

| 类别 | 内容 |
|---|---|
| **必做** | 1 个监测节点、1 个接收端、1 套双支路台架、1 套巡检软件、三类数据、论文与报告 |
| **争取** | 干管参照测点、突发采样、流量阶跃检测、软著 |
| **不做** | 田间实测部署、多支管组网、滴灌带级诊断、自动阀门控制、云平台与 App、漏点精确定位 |

**一句话边界**：在实验室台架上，用一个支管节点，回答"正常轮灌切换与支管故障怎么区分"，并把答案做成能提示到"哪根支管该去看看"的原型。

## 1.3 为什么做得成

| 支撑 | 说明 |
|---|---|
| 就在场景里 | 学校所在地阿拉尔已有 25 万亩自动化灌溉，调研方便 |
| 差异化清楚 | 已有设备测毛管/田间；本项目测**支管**，核心答"切换与故障如何区分" |
| 边界清楚 | 不做田间部署，只需实验室台架，可控 |

# 二、测量与采集

## 2.1 这一步要解决什么

把"能不能看出水量变化"变成**能买到、买得起、装得上**的器件参数。

## 2.2 做法

### （1）测点布置

```
　　　　　　P0　　　　　　　　　　　　P1
　　　　　　 │　　　　　　　　　　　　│
水源 ── 干管 ─┴── 受限元件 R ────────┴── 流量计 Q ──→ 正常出流
　│　　　　　　　　　　　　　　　　　　　　　└──→ 泄漏旁路（可控）
　└─→ P2（干管参照）　　　　差压 ΔP = P0 − P1 由差压变送器直接测得
```

**四路信息**：差压 ΔP、干管参照 P2、流量 Q、由此推出的下游压力 P1。

### （2）用差压取代"两只表压相减"

| 方案 | 不确定度 | 5% 变化时 信号/不确定度 | 能否用 |
|---|---|---|---|
| 两只 0—200 kPa 表压相减 | 0.74 kPa | 0.70 / 1.04 / 1.39 | ❌ 三档全不可分辨 |
| 单只 0—35 kPa 差压 | 0.088 kPa | 5.9 / 8.8 / 11.8 | ✅ 达标 |
| **单只 0—20 kPa 差压** | **0.050 kPa** | **10.3 / 15.4 / 20.6** | ✅ **最优** |

**原因**：原方案用 200 kPa 量程测 5—10 kPa 压差，量程是信号的 20—40 倍，而精度按满量程百分比给出，误差被等比放大。**这是量程选择的问题，换更贵的表压表解决不了。**

### （3）量程的选择依据

健康压降在最高供压档达 **9.33 kPa**，量程需留 1.5 倍过载余量：

```
量程 ≥ 9.33 × 1.5 ≈ 15 kPa  ⇒  只能选 20 kPa 或 35 kPa
```

### （4）器件选型

| 项目 | 型号 | 关键指标 |
|---|---|---|
| **差压变送器** | 麦克 MDM490 系列 **0—20 kPa**，4—20 mA | ±0.25%FS，**耐静压 ≥160 kPa**，316L |
| 干管参照 | MPM489 0—200 kPa | 只看趋势 |
| 主控 | STM32F103C8T6（可换 GD32F103） | 64 KB / 20 KB |
| 采集 | **SGM58031**（pin 兼容 ADS1115） | 16 位 Σ-Δ，I²C |
| 流量计 | SEN0549 | 0.3—5 L/min，540 脉冲/L |
| 无线 | E220-400T22D ×2 | 410—493 MHz |

### （5）采集节拍

| 状态 | 采样率 | 用途 |
|---|---|---|
| 常态 | 1 Hz | 主判据 |
| 突发（争取） | 100 Hz × 2—5 s | 阀门动作的秒级过渡 |

主窗 **10 秒**（11 个计数端点 + 10 次压力观测），短窗 **3 秒**（关注提示）。

## 2.3 为什么做得成

| 验证 | 结果 |
|---|---|
| 差压能否分辨 5% | 20 kPa 档 U=0.050 kPa，信号/不确定度 **10.3—20.6**，余量充足 |
| 流量计数够不够 | 10 秒窗相对分辨率 **0.278%**，优于 5% 目标一个数量级 |
| 器件能否买到 | 国内有 4 家渠道（麦克、熙正、天康、三丰）；已备 4 条替代路线 |
| 万一低量程买不到 | 退 **0—35 kPa**（信噪比 5.9—11.8，**仍达标**）；再退 MDM290 芯体自建调理 |
| 万一 5% 测不出 | 正式目标退到 **10%**，5% 写成边界情形——**这是提前知道边界，不是失败** |

**本环节结论：可行。** 差压方案把量程/信号比从 20—40 降到 2—3.5，且接口（4—20 mA + 150 Ω）与既有设计一致，改动小、成本可控。

# 三、建模与标定

## 3.1 这一步要解决什么

建立"压力—流量—阻力—负载"的可计算关系，并验证**它在本项目的测量条件下真的能辨识出来**。

## 3.2 做法

### （1）水力模型

```
区段压降：  ΔP = P0 − P1 = R · Q²
下游负载：  Q  = C · √P1
```

由这两个关系派生出两个**可解释的特征量**：

```
K  = Q / √P1            下游等效负载系数（分流能力的度量）
R̂  = (P0 − P1) / Q²      区段等效阻力（阻力的度量）
```

### （2）一个必须说清楚的前提：单一工况下不可辨识

把模型联立消元：

```
P1 = Ps − Rc·Q² − R·Q²        （串联阻力：上游共同阻力 Rc + 本支管阻力 R）
Q  = C·√P1                     （负载关系）

消元得： P1 = Ps / (1 + (Rc + R)·C²)
　　　　 Q  = C·√Ps / √(1 + (Rc + R)·C²)
```

**关键**：联合量 **β = (Rc + R)·C²** 一个标量决定一切。

> **⇒ 在单一工况下只能辨识 β，无法把上游共同阻力 Rc 与本支管阻力 R 分开。**

**实测印证**：`Q/√P1` 全程恒为 **0.280**（说明 C 可辨识），而 `(P0−P1)/Q²` 中混着 Rc 的成分——**这正是"上游供压变化"与"本支管故障"在单支管测点上不可分的数学原因。**

### （3）标定必须跨工况

实测发现，同一工况内压力只波动约 **0.3%**，在这么窄的跨度上拟合曲线，斜率完全由噪声支配：

| 拟合窗口 | 得到的指数 |
|---|---|
| 单一工况内（20—119） | **−0.228**（明显错误） |
| **跨工况（20—359）** | **+0.4915**（正确） |

**⇒ 台架必须用 80 / 120 / 160 kPa 三档供压，跨档合起来压力跨度约 100%，才能得到正确的曲线。**

### （4）健康参照要分档

`gain`（增益）、`r₀`（健康阻力）、`s`（稳健尺度）**按"供压档 × 阀态"分档标定**，形成一张健康参照表：

```
健康参照表 = { (供压档, 阀态) → (gain, r₀, s_Q, s_R) }
```

## 3.3 为什么做得成

| 验证 | 结果 |
|---|---|
| 模型是否成立 | 用仿真观测反推得 **R=0.79、C=0.280、指数 n=0.49**，与设计值 R=0.8 / Cₙ=0.28 / n=0.5 **一致** |
| 指数能否辨识 | 跨度 1% → 指数不确定度 1.00；**跨度 20% → 0.0055**。三档供压跨度约 100%，足够 |
| 标定是否可重复 | 健康残差尺度仅 **s_Q=0.0025、s_R=0.015**，远小于判据阈值 |
| 有什么必须补做 | **流量计自身压损曲线**（0.5—10 kPa，与信号同级）必须实测并写入标定记录 |

**本环节结论：可行，但有一处必须补做。** 模型已用实测反推核实；唯一必须补的是流量计压损曲线实测，否则压损会污染 R̂ 估计。

# 四、判据与验证

## 4.1 这一步要解决什么

设计能**把"正常轮灌切换"与"真实故障"分开**的判据，并给出它的检出边界。

## 4.2 做法

### （1）先看清轮灌切换的真相

实测一条含 B 支路开关的轨迹：

| 时段 | P0 | Q | **负载 C** | **阻力 R̂** |
|---|---|---|---|---|
| B 阀关 | 116.6 | 2.931 | **0.280** | **0.79** |
| **B 阀开** | **104.1** | **2.780** | **0.280** | **0.79** |
| B 阀关 | 116.7 | 2.933 | **0.280** | **0.79** |

**切换使 P0 骤降 10.7%、Q 降 5.2%，但 C 与 R̂ 完全不变。**

> **⇒ 轮灌切换只是换了一个工作点，不是故障。**

### （2）由此确定判据的设计原则

> **判据不建立在参数的绝对值上，而建立在"同一工况内、参数相对该工况健康参照的漂移"上。**

| 现象 | 负载 C | 阻力 R̂ | 判据输出 |
|---|---|---|---|
| 轮灌切换 | 不变 | 不变 | **不报警**（仅记录工况已变） |
| 等效泄漏 | **升高** | 基本不变 | 泄漏候选 |
| 等效受限 | 基本不变 | **升高** | 受限候选 |
| 上游供压变化 | 同向变化 | 同向变化 | 待检查（需干管参照） |

### （3）用累积和（CUSUM）取代固定阈值

```
归一化： z = 残差 / 稳健尺度（1.4826×MAD，取自同工况健康段）
累积：   S_t = max(0, S_{t−1} + z_t − k)，k = 0.5
报警：   S_t > h
```

**为什么用 CUSUM**：对"变化幅度未知"的检测问题，累积和在给定虚警率下使最坏情况检测延迟最小；而且**门限可以由目标误报率反推**，把"1 次/小时"从一个事后统计变成设计输入。

### （4）门限由数据反推，而不是拍定

**第一步**：算健康段的 CUSUM 峰值分布（40 条/档）

| 噪声 σ (kPa) | P50 | P90 | 最大 |
|---|---|---|---|
| 0.3 | 25.5 | 39.2 | 43.7 |
| 1.0 | 23.6 | 34.5 | 46.4 |
| 3.0 | 24.6 | 35.0 | 47.0 |
| 10.0 | 26.9 | 37.5 | **50.6** |

**第二步**：门限取健康峰值最大值留 20% 余量

```
h = 50.6 × 1.2 ≈ 61
```

**第三步**：验证

| 门限 h | 健康段误报 | 故障段检出 |
|---|---|---|
| 5 | **40/40** | 40/40 |
| 20 | 26/40 | 40/40 |
| 40 | 2/40 | 40/40 |
| **61** | **0/40** | **40/40** |

> **⇒ h=61 给出"健康零误报、故障全检出"的干净分离。**
> 这也说明：原设计的固定阈值（0.06 / 0.6）相当于门限过低，缺乏误报率依据。

**第四步**：四类现象一并检验（h=61）

| 类型 | σ=0.3 | σ=1.0 | σ=3.0 | σ=10.0 |
|---|---|---|---|---|
| 泄漏 | 40/40 | 40/40 | 40/40 | 40/40 |
| 受限 | 40/40 | 40/40 | 40/40 | 40/40 |
| 漂移 | 40/40 | 40/40 | 40/40 | 40/40 |
| 负载未知 | 40/40 | 40/40 | 40/40 | 40/40 |

**健康段误报全部为 0。**

### （5）可检边界（本项目的核心产出）

**泄漏幅度**

| 相对流量增量 | 检出率 |
|---|---|
| 1%—5% | **0/10（不可检）** |
| **8%** | **10/10** |
| 10%—30% | 10/10 |

**幅度 × 时长二维边界**

| 幅度\时长 | 5 s | 10 s | 20 s | 40 s | 60 s |
|---|---|---|---|---|---|
| 3% | 0/10 | 0/10 | 0/10 | 0/10 | 0/10 |
| 5% | 0/10 | 0/10 | 0/10 | 0/10 | 0/10 |
| **10%** | 0/10 | 0/10 | **7/10** | **10/10** | 10/10 |
| 20% | 1/10 | 10/10 | 10/10 | 10/10 | 10/10 |
| 30% | 6/10 | 10/10 | 10/10 | 10/10 | 10/10 |

**读法**：5% 在任何时长下都不可检；10% 需持续 ≥20 秒；20% 只需 10 秒；30% 在 5 秒内已有 6/10。

**受限幅度**

| 阻力增量 | 检出率 |
|---|---|
| +10% | 1/10 |
| +20% | 8/10 |
| **+30%** | **10/10** |

**⇒ 受限比泄漏更容易检出**（压差对阻力是线性关系，对流量是平方关系）。

### （6）对测量精度的要求

注入 20% 泄漏、持续 80 秒，叠加不同水平的压力测量噪声：

| 测量不确定度 U (kPa, 1σ) | 检出率 | 误报率 |
|---|---|---|
| 0—1.0 | 10/10 | 0/10 |
| 1.5—5.0 | 10/10 | 0/10 |

**⇒ 在 U ≤ 5 kPa 范围内判据表现稳定**，说明**瓶颈在故障幅度，不在传感器精度**。

### （7）干管参照的作用（如实说明）

我们检验了"用干管参照扣除共同扰动"能否降低误报。结果显示：**在本项目现有仿真数据上，参照差分带来的改善不显著（约 −12% 至 +20%，属噪声范围）**。

原因有两点，都值得记录：
1. 现有数据中的供压扰动**本身未使判据误报**（健康段误报 0/40），没有可改善的空间
2. 参照信号是从同一组观测反推的**合成量**，不含真实独立测量的信息

**⇒ 干管参照的真实价值必须由台架实测判定**（已列入台架实验项）。这一条我们**不写成"必然有效"**。

## 4.3 为什么做得成

| 验证 | 结果 |
|---|---|
| 门限是否有依据 | 由健康段峰值反推 **h=61**，健康 **0/40** 误报、故障 **40/40** 检出 |
| 四类是否可分 | 四类均 40/40 检出，误报 0/40 |
| 能否给出边界 | 已得"5% 不可检、8% 可检"与二维边界 |
| 精度要求高不高 | U ≤ 5 kPa 均达标，**普通工业变送器足够** |
| 与已有工作的区别 | 目的是**检测**不是控制；方法为参数漂移 + 累积和（与专利 CN122546648A 目的、方法、输出、场景四项均不同） |

**本环节结论：可行，且已得出明确边界。** 关键结论是"**5% 不可检、8%—10% 可检**"。这比硬报高识别率更可信，也直接决定申报书目标该怎么写。

# 五、通信与平台

## 5.1 这一步要解决什么

把数据从田间接出来、传回电脑、变成**泵工看得懂的一句话**。

## 5.2 做法

### （1）通信

| 项 | 设计 |
|---|---|
| 帧结构 | 公共头 16 B；快照 35 B；遥测 55 B；**事件 57 B**；应答 24 B |
| 封装 | CRC16 校验 → COBS 编码 → 0x00 定界 |
| 身份 | 设备号 + 会话号 + 序号，应答在数据落库后回复 |
| 队列 | 常规 16 槽 + 事件优先 1 槽 + 重传缓冲 64 槽 |
| 可靠性 | 初始派发 ≤8 次，恢复派发 ≤4 次，会话寿命 300 秒 |

**时间预算核算**：最大帧 57 B，在 2.4 kbps 下空中时间约 **190 ms**；57 B 小于协议 64 B 分包上限。

### （2）上报时机（本项目的关注点）

一条支管一天只有 1—4 小时有流量。**本项目不重复验证"事件触发能省多少"，而是回答：**

> **在这种灌水节拍下，什么时机上报最划算、会不会漏掉故障？**

### （3）软件分层与工作量

| 层 | 内容 | 状态 |
|---|---|---|
| 节点固件 | 采集、质量门控、诊断内核、日志、协议、无线 | 新增约 54 人天 |
| 接收服务 | 串口读入、解帧去重、SQLite、应答、断连恢复 | **已完成** |
| 巡检平台 | 八页面、核查/复测留痕、导出、三维装配 | **已完成** |
| 离线分析 | 标定拟合、阈值扫描、统计作图 | **本次已建** |

**节点固件实施顺序**（先通链路、后加能力）：

```
S1 点灯串口 → S2 单通道采集 → S3 双通道+计数 → S4 落盘（能力门槛）
→ S5 移植诊断内核 → S6 无线收发 → S7 接入接收服务 → S8 队列与恢复 → S9 台架联调
```

> **S4（能写进 SD 卡并读出来）是能力分水岭**：只会在串口打印还不算会。

### （4）输出形态（面向使用者）

```
【提示】3 号支管本次灌水比同压力健康状态少出 12% 的水
【判断】压差升高、阻力 R̂ 增大，负载 K 基本不变 → 倾向于"受限"
【建议】检查该区段接头、阀门与过滤器
【时段】本次灌水窗口 10:20—10:52，已确认 3 次
```

输出的是**一句话 + 建议部位**，不是一堆曲线。

# 本路线的三个特点

**一是六步递进、环环相扣。** 每一步回答一个必须回答的问题，前一步的产出就是后一步的输入，逻辑链闭合。

**二是每一步都说清了"为什么做得成"。** 六步全部给出验证结果与退路，没有"只许成功"的环节。

**三是结论敢于说边界。** 明确写出"**5% 不可检、8% 可检**"、"受限最小 **+30%**"、"测量精度 **U ≤ 5 kPa** 即可"；对干管参照的作用如实说明"**现有数据上改善不显著，需台架实测判定**"。

> 一份申报书里，**说清"什么情况下做不到"，比硬报一个高识别率更让人信服。**
