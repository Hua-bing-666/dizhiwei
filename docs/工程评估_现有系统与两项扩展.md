# 支管故障诊断项目的工程评估

日期：2026年10月5日。目的：核查现有系统及公开实现，判断事件触发和阀门控制是否值得加入本期。本文是技术决策依据，不直接作为申报正文或已完成成果证明。

## 1. 本轮判断

保留“双压力—流量观测、工况约束诊断、LoRa告警及巡检复核”为主线。事件触发作为有依据、需要对照验证的重点扩展，研究价值落在减少开销时能否保持故障辨识及时性，而不是仅有自动改变周期的功能。真实阀门不列为本期必须交付；控制请求、模拟执行和执行接口保留为轻量辅助任务，在主线稳定后实现。系统完整性已经由节点、通信、接收存储、管理软件与复核流程构成，不需要靠增加实物阀门才能称为系统。

这一结论保留用户原定调，但进一步明确任务优先级。公开资料支持相关功能能够实现，不证明本项目性能已经达成；关阀及事件策略的现成实现也意味着不能把功能名称本身当作原创性证明。当前尚未完成真实传感器、无线节点和田间运行，工程可行性需逐级验证。

## 3. 从工程角度看事件策略

首先确定优化对象。传感器实际转换、完整记录与无线发送是不同的动作。如果两路压力和流量仍每秒完整读取，系统只是减少写盘及发送，那么应称为分级记录或事件上报，而不是节省了采样。若减少完整采集，必须交代触发通道观测什么、多久观察一次、其成本及不能识别的变化。触发后增加采集不会补回触发前缺失的数据。

建议用稳定运行、变化待确认和异常记录三种状态组织采集。触发条件同时检查变化幅度和持续趋势，避免只看一阶变化率而漏掉缓慢泄漏；阈值按健康波动和测量误差确定，进入与退出条件分别设置，避免反复切换。工况切换及数据质量状态继续使用原诊断规则，触发只是要求增加证据，不代表已经识别故障。

采集周期改变后，滤波与确认须用实际时间定义。原基线的10样本均值和连续5样本确认，在1秒及60秒采集下对应的时间尺度完全不同，不能原样比较后把差异归因于策略。滚动脉冲窗口同样需要保留真实起止时刻。先固定被评价的诊断条件，再设计不同采集/上报策略的公平对照；如果因观测不足无法保持同一时间窗口，明确报告缺失和等待时间。

本项目当前合成对照尚未证明K/R方法优于固定流量阈值：既有低噪声组两者均成功，高噪声组K/R出现较多故障前确认误报。事件策略不能把这些误报隐藏为少发送，也不能只对触发后的片段计算识别率。正式评价覆盖全部运行时间，包括未触发、迟触发和错误触发，并继续通过独立操作及参考测量确定故障程度。

可研究的问题是：在相同误报约束下，怎样使监测开销和通信负担降低，而有效提前量及漏检仍满足目标。对照保留固定高频、固定低频、单独事件上报，以及拟设计的分级采集。评价误触发、漏检、首次正确提示、本地/远端延迟、监测转换次数、完整记录及发送数量。能耗待实物测量，允许出现“减少发送，但整机能耗差异不显著”的结果，不预先安排节能结论。

## 4. 已完成的理想时序核查

本轮新增并运行`simulation/event_monitoring_bounds.py`，采用均匀故障发生相位，核查每隔T秒监测时的首次可见等待。变化一旦被观察即可识别，不含噪声、转换、流量窗口、持续确认或无线时延，是理想时序分析，不是诊断仿真准确率。

| 触发监测间隔 | 平均等待 | 持续变化在60秒内被观察的理想比例 |
| --- | --- | --- |
| 1秒 | 0.5秒 | 100% |
| 10秒 | 5秒 | 100% |
| 60秒 | 30秒 | 100% |
| 600秒 | 300秒 | 10% |

表中结果按随机发生相位的假设计算，已用每种周期1200个中点相位与解析结果核对。持续异常最终仍可被观察，不能将60秒内未看见写成永久漏检；短时变化可能发生在两次监测之间。算法处理和实际测量还会增加等待。由此建议将10分钟作为低频完整记录或对照配置，而不直接作为早期故障的唯一监测周期。原始结果保存在`simulation/event_monitoring_review/ideal_polling_bounds.csv`及JSON中，未生成任何能耗数值。

## 5. 关阀的必要性与任务层级

关阀对严重泄漏具有潜在处置价值，但对局部受限通常不能修复故障，关阀还会中断剩余正常灌溉。是否应自动关闭，取决于工况是否已知、故障证据是否充分以及误停水的代价，不能统一写成“异常就关阀”。相似的未知正常负载变化与泄漏在现有观测下可能无法区分，这一辨识边界不能靠增加执行器解决。

本期投入真实关阀，需要驱动、供电、安装、到位及止流复核、动作瞬态评价和独立控制试验，工作量会与诊断主线竞争。若只点亮LED，其收益是验证处置请求、人工操作与记录流程，适合作为辅助集成；它不增加实物止损证据，不作为论文主要贡献。既有诊断数据也不会因另开展控制试验全部失效，问题在于不能把关阀改变后的工况混入原来的未处置对照。

因此本期保留控制请求及演示、接口预留，真实隔离作为后续发展方向，优先完成可观测、可辨识、可传输的主线。未来接入真实阀门时，分别测量误关阀、真实止流时间、残余流量、独立收集的累计泄漏量和相邻支路变化，再判断从告警到止损的实际收益。

## 6. 对申报书写法的调整

参照国家级示例的组织方式，将应用问题、完整系统、重点方法和验证任务连贯展开；不模仿没有证据的性能承诺。系统工程任务写充分，创新点集中于可检验的方法问题，控制模拟以适当篇幅放入系统集成与后续拓展。已实现、拟研究与后续接口通过所属章节和准确动词表达，不在每段堆放“待确认”。

总体设计可采用下面的主干文字：

> 本项目面向南疆规模化棉田膜下滴灌的轮灌支管巡检需求，构建双压力—流量感知、LoRa事件传输与本地巡检管理相结合的物联网原型系统。针对供压波动、轮灌切换与渐进故障容易混淆的问题，研究运行工况约束下的异常辨识方法，并将异常提示关联至监测支管和测点区段。在参考标定与健康建模基础上，开展分级采集与事件上报对照，评价减少监测及通信开销时的故障检出、误报和有效提前量；通过双支路清水台架、独立参考测量和留出批次形成方法及系统验证依据。平台衔接人工核查、模拟控制与复测记录，预留真实执行器接口，为后续棉田验证及支管隔离研究提供基础。

接下来的前期验证按采集调度实现、正常扰动与两类故障对照、真实采样成本核对三个环节推进。先得到能够支持取舍的结果，再把策略、图源和实验安排写入最终申报书。现有图片精简、黑白适配、预算留空和逐页排版要求继续执行，不因扩展功能而放弃。
