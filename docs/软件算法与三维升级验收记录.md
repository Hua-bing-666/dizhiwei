# 运行平台 V1.1 分项验收记录

验收日期：2026年10月7日。对象为主机软件、合成数据与概念三维台架；申报书和用户已修改的 Word 文件不在本轮变更范围。界面采用正常功能名称，版本标识为 V1.1，不使用“升级版”等宣传式标题。

## 软件接入

已将时序适配、编译后的 C 核心、V2 协议接收与 SQLite 接入 HTTP 服务。网页离线模式使用同一 C 核心生成的27组回放，不再用前期 K/R 阈值结果冒充当前算法。网站包括总览、监测、事件、设备、历史和设置六个模块。趋势保留缺测断线，窗口特征只用于展示，判定以 C 输出为准。

后端有30项定向检查通过：631个输入点逐项与独立有理数算法参照核对；重复报文幂等；消息或快照内容冲突拒绝；CRC损坏和未知配置无 ACK；独立数据库连接确认 ACK 对应的协议事务已提交；核查记录追加且不改变算法快照；重启后的历史会话不标为实时；压力缺测与计数复位保留质量事件并重建窗口；控制请求、软件收到、模拟执行及复位分开保存。标定工具能恢复无噪声合成幂律，但候选配置不自动批准、不启用短窗、不覆盖运行参照。

HTTP仅监听本机回环地址，拒绝跨来源写入，不发布源码、数据库或 Word 文件。页面通过单次接口获取相互一致的状态和采样集合。采样按单线程请求推进，没有后台伪造实时节点状态。原始压力时序来自软件输入约定，尚未验证 ADC、串口或 MCU 中断。

## 算法实验

健康参照训练、C演示与策略挑战种子分离。432组采集策略组合包含3个测试种子、3档压力噪声、6类场景以及1/2/5秒巡航间隔的全部相位。各组合共享模型与部分噪声轨迹，不应视为432次独立实物试验。

| 策略 | 渐进泄漏有效早期 / 组合数 | 渐进受限有效早期 / 组合数 | 正常场景平均压力读取次数 |
|---|---:|---:|---:|
| 固定1秒 | 9 / 9 | 9 / 9 | 601.0 |
| 2秒巡航，触发后1秒 | 17 / 18 | 17 / 18 | 411.6 |
| 5秒巡航，触发后1秒 | 39 / 45 | 42 / 45 | 273.6 |

这些结果表明稀疏读取存在代价，不能直接把5秒设为默认策略。8秒短时异常在稀疏策略中出现漏检或恢复后迟发候选；入口压力漂移仍会造成受限候选误报。网页保留了这些结果，不只展示成功案例。主线继续采用固定1Hz，2/5秒策略仅保留为独立研究对照，不向C核心注入保持值来模拟高频采样，也不据读取减少宣称节能。

另有72组 C 固定参照的未见工况挑战，供压90/150kPa，负载指数0.3/0.5/0.8，两个新随机种子与两档压力噪声。指数0.5的正常对照8组未出现候选误报，泄漏与受限各8组达到本模型的有效早期判据；指数0.3或0.8的正常对照出现误报。这支持后续多工况健康参照标定方向，不支持跨任意滴灌负载直接部署的主张。

## 三维结构

保留原水路、取压位置、A总流量位置和B健康切换支路，增加带三个过线开口的防溅板及两个配套安装孔。交集检查曾发现旧线缆包络穿板，已改为从接头后端接入并重新检查。最终新增板与原构件实体交集为零；盒盖后缘与板间概念间隙3mm，回水管与板间8mm。

STEP重新打开后207个实体有效，导出的GLB/OBJ与网页来自同一几何。浏览器核查轴测、俯视、取压、泄漏计量与电子盒局部的标注位置、文字框间距及手机显示。防溅板不等于防水认证；实体检查也不等于全装配公差和供应商安装要求通过。

20秒分次计量和安全液位有效容量≥440mL的要求保留。679mL是几何内腔计算，不是标定结果。长时排水、阀门水锤、流量计实际直管段与器件尺寸须在采购和实物台架阶段验证。

页面与模型截图采用浏览器实拍，先看全量联系表，再重点核查总览、手机监测、事件表、核查对话框、参照拟合和模型局部。修正了页面切换重复渲染会关闭刚展开的实验面板的问题。旧版浏览器存储保留，只读导出，不混入当前 C 快照。
