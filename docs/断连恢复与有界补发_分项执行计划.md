# 断连恢复与有界补发：第八轮执行计划

2026年10月6日。承接第七轮120秒中断仍缺失事件的问题。本步只研究主机参考传输恢复，不改诊断规则、采集频率、申报书、网站、三维或控制功能；保留第七轮全部源文件和失败结果。

## 一、冻结设计

普通遥测帧兼作链路探测，不增加无线协议类型。30秒一次探测使用最近输入的快照；不把探测时刻写成采集时刻。仅匹配身份与指纹、且在最近一次派发后8秒内到达的有效ACK作为近期双向链路证据，不能由仿真中断结束时间直接触发恢复。无近期确认时表示连接未知，不把AUX就绪当作接收成功。

首次持续探测版本已完成576组回放并单独保存；其清洁链路字节量约为原候选的3.16倍，因此在本工作包内修订为条件探测：存在已派发且至少8秒未获确认的业务消息，同时8秒内没有其他有效ACK时，才启动最多30秒一次的探测。无待确认消息或正常即时确认时不探测。修订前全部结果和代码保留；原48000/48001种子结果已看过，修订后不再称独立留出，另外冻结未使用的49000/49001种子、随机丢失/重复中断/ACK全丢三种条件，形成72组留出对照。

每条业务消息保留原设备、会话、序号、字节与采集时间。沿用最多8次初始派发，间隔为2、2、2、20、20、20、20、20秒；恢复后每条最多追加4次、间隔2秒，全生命期不超过12次派发预留。再次中断或重开发送端不得重置预算。300秒保留期限不延长，期限到达停止派发并明确记过期；晚到ACK只能追记，不能重新激活历史记录。

未确认消息（包括耗尽预算后停放的消息）共用16个业务槽；探测单独预留1槽，避免业务队列满时无法探测。终态与拒绝记录共用64条历史环，超过后淘汰最旧记录；当前会话已淘汰事件设置来源水位，拒绝重新入队，防止历史裁剪引入重复。记录拒绝、过期、预算耗尽和历史淘汰累计数。这里只限制逻辑记录与帧字节，不宣称SQLite文件或STM32存储已满足该大小。

## 二、分项验收

| 分项 | 具体工作 | 验收标准 |
|---|---|---|
| 8A 恢复与身份 | 独立实现有界发送端；复用已验证编解码/接收端 | 只有有效、及时、实际派发过的ACK可触发恢复；错误/迟到ACK不得激活；原身份与正文不变；重开和重复事件不重置次数；未知时钟和旧快照仍不得显示为实时 |
| 8B 预算与容量 | 未确认槽、探测槽、历史环和过期分开；时间与来源水位检查 | 初始≤8、追加≤4、总计≤12；再次断连、重开不能绕过；边界满队列、过期、历史淘汰与重新入队均明确可查；至少1000条连续记录后逻辑槽不增长 |
| 8C 配对回放 | 先冻结，再复用上轮主轨迹/新种子边界，与上轮候选对照；补充新种子重复中断 | 同事件源与链路随机数；探测字节计入开销；分别统计生成/接收/缺失、拒绝、过期、待发、恢复次数、重试与首次延迟；不预设全部送达；保存360秒中断过期及容量不足反例 |
| 8D 图表与收尾 | 仅绘制解释恢复机制和效果边界的图 | 图中节点、线型、单位、样本定义正确；灰度可区分；文字边界/碰撞检查及最终PNG逐张查看；原始结果、源代码摘要与复算验收齐全 |

主回放仍使用72条合成轨迹、三种链路；边界复用上轮12条新种子轨迹的20/120/360秒中断。新增种子48000、48001，三种场景、两档噪声，对比两次中断[350,410)与[440,500)，以及ACK单向丢失和全程不可达。旧策略直接用旧实现复算，不改旧文件。效果改善不等于无线实测，正常进程重开也不等于突然掉电验收。
