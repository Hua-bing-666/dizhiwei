# 一、项目方案现状

## 1.1 真实问题

南疆棉田膜下滴灌是**轮灌**：一根支管一天只灌 1—4 小时，其余时间静压，阀门切换 1—5 分钟一次。泵工/管护员**不缺数据，缺的是"哪根支管该去看一眼"**——因为开阀关阀、供压波动本身就会让压力和流量变化，和真故障长得几乎一样；人工巡检一趟周期长，等发现时水已经跑掉。

## 1.2 研究对象与两类故障

| 故障 | 物理含义 | 等效参数 | 可用特征 |
|---|---|---|---|
| 等效泄漏 | 支管下游跑水（接头、旁路） | 负载系数 `C` 增大 | `K = Q/√P1` 上升 |
| 等效过流受限 | 测点之间过流断面变小（堵、夹扁、阀半关） | 区段阻力 `R` 增大 | `R̂ = (P0−P1)/Q²` 上升 |

**"早期"的定义**：不是"几秒内"，而是**在第几次灌水时发现**。15 秒的检出延迟只占 7200 秒灌水窗口的 0.2%，根本不是瓶颈；真正的价值是"这次灌水就发现"还是"跑三趟才发现"。

## 1.3 三个研究问题（`项目场景与边界_大创版.md`，尚未进申报书正文）

1. 供压变化与邻支路切换，会不会让这套判据误判？
2. 在给定的传感器不确定度下，**多大的故障才分辨得出来**（可检边界）？
3. 只在灌水时段采集、事件触发上报，会漏掉多少、省下多少（通信取舍）？

## 1.4 三档边界

| 档 | 内容 |
|---|---|
| **必做** | 1 个 P0/P1/Q 感知诊断节点 + 1 个 LoRa 接收端 + 1 套双支路清水台架 + 本地 Web |
| **争取** | 真实棉田一个灌溉季的验证、论文投稿、软著 |
| **不做** | 单滴头定位、自动阀控、云平台、太阳能供电、多节点组网、水质监测、水锤分析 |

## 1.5 创新点定位

**现在写的**（弱）："用了差压 + LoRa + CUSUM"——这些全是成熟器件与教科书方法，评委一问就散。

**建议改成的**（强，且可证明）：

> **① 可检边界**：在多大的测量误差与供压波动下，双测点方法开始赢过单流量基线，以及什么时候反而更差。
> **② 结构性不可分辨**：供压变化、邻支路开关对 `K`/`R̂` **严格不可见**（模型内代数恒等，不是"鲁棒性好"）；受限与 P0 传感器偏置**共线，任何算法不可隔离**。
> **③（待验证）把轮灌切换从"要压制的干扰"改成"辨识所需的激励"**：单工况内 P1 只波动 0.26%，指数 `n` 不可辨识；跨 80/120/160 三档供压后跨度约 100%，才得到 `n=0.49`。

第 ③ 条的前提是**先做 E1 实验**确认滴灌带是否压力补偿式（`n≈0` 还是 `0.5`）。若 `n≈0.5`，该条失效，退回 ①② 两条——**保底档照样能结项**。

# 三、仿真与建模现状（详细）

## 3.1 水力稳态模型（`simulation/diagnosis_feasibility.py:20-26`）

三条稳态关系：

```
P0 − P1 = R·Q²              区段阻力（两测点之间）
Q      = C·√P1              下游负载（含正常负载 Cn 与泄漏 Cl）
Ps − P0 = Rc·(Q_A + Q_B)²   上游共同阻力（双支路共享）
```

闭合解：`P1 = Ps / (1 + (Rc+R)·C²)`，`Q = C·√P1`。

参数（申报书取值，已被留出数据反推印证）：`Cn=0.28`、`R=0.80`、`Rc=0.40`、`n=0.5`。

**可观测性结论**：测 3 个量 (P0, P1, Q)，未知 3 个量，**恰好定解、零冗余**。由此推出四条硬结论：

| # | 结论 | 性质 |
|---|---|---|
| 1 | 供压变化、邻支路开关对 `K`、`R̂` **严格不可见** | 模型内代数恒等 |
| 2 | 泄漏与受限**正交**，可隔离 | 灵敏度矩阵为对角阵 |
| 3 | 受限 与 P0 传感器偏置**共线，任何算法不可隔离** | 只能靠定期标定 + 输出"待核查" |
| 4 | 二维联合检测器（T²/PCA-SPE/马氏距离）**数学上零增益** | 对角阵 ⇒ 退化为两个独立一维问题 |

第 4 条直接否掉了几项"看起来更高级"的加法（BOCD 假设分段常数、与斜坡故障模型误配，也已否掉）。

## 3.2 合成试次生成器（`diagnosis_feasibility.py`）

| 项 | 设定 |
|---|---|
| 时间轴 | t = 0—600 s；B 支路阀在 180—300 s 打开（制造邻支路扰动）；故障 **360 s 起斜坡注入** |
| 故障类型 | `normal` / `supply`（供压 120→90）/ `leak`（C + 0.09·ramp）/ `restriction`（R + 4·ramp）/ `drift`（P0 + 10·ramp）/ `load_unknown`（负载未知变化） |
| 噪声 | 压力 σ ∈ {0.3, 1, 3, 10} kPa；流量 σ = 0.02 L/min；零均值独立 |
| 规模 | 4 档噪声 × 6 类型 × 20 seed = **480 试次** |
| 特征 | 10 s 因果滑动平均 → `K = Q/√P1`、`R̂ = (P0−P1)/Q²`；`P1>10 且 Q>0.5` 才判有效 |
| 标定 | 只用每条轨迹**前 120 健康秒**取中位 `K0`、`R0`（不碰被评价段，避免数据泄漏） |
| 判据 | `K/K0−1 > 0.06`；`R̂−R0 > 0.6`；连续 5 次同标签确认 |

**失效判据**：相对健康流量偏离 ≥15% 作为"演示失效判据"，文档已注明**非农学或学校标准**。

## 3.3 留出观测复核（`simulation/project_review/lib_sim.py`）

- 数据源：`cusum_review/heldout_observations.npz`
- 反推核实：`R` 中位 **0.7928**、`C` 中位 **0.2799**、log-log 指数 **0.4914** —— 与申报书一致
- 标定窗 t=20—119 s；监测起点 130 s；故障起点 360 s
- 健康残差稳健尺度：`s_Q = 0.00247`、`s_R = 0.01514` ⇒ **原阈值（0.06 / 0.6）是噪声尺度的 24—40 倍**，几乎不可能误报，但也意味着只检得出大故障

## 3.4 三类判据对照

| 判据 | 结构 | 结果 |
|---|---|---|
| 原双阈值 | 残差 > 固定阈值 + 连续 5 次确认 | σ=0.3—1 kPa 泄漏 **0/40**；σ=3 kPa 时 37/40 |
| CUSUM（h=5） | 稳健归一化 → 双路累积 | 泄漏 **40/40**；但健康段误报 **40/40**（ARL₀ 0.22 分钟） |
| CUSUM（h=61） | 同上，门限按"零误报"反推 | 误报压住，但小幅度故障检出掉到 0 |

**⇒ 现在的 h=61 是把误报压到零换来的，代价是牺牲了小故障灵敏度。这正是"必须做门限扫描"的原因。**

| **E3** | CUSUM 门限 h 与 ARL₀ | h=3—10 时 ARL₀ 均值仅 0.15—0.68 分钟 ⇒ **教科书默认 h=5 完全不可用** |
| **E4** | 切换敏感性（时长 1—60 s × 幅度 5—20%） | 原判据 0/12 误报；CUSUM 10—12/12 误报 ⇒ **CUSUM 对切换敏感，必须配合工况分层** |
| **E5** | 干管参照差分收益（供压扰动） | 无参照 40/40、有参照 40/40 ⇒ **零收益** |
| **F1/F2** | 同上，另一组场景 | 加参照后误报 **10/40 → 40/40**（**恶化**） |
| **E6** | 二维可检边界（幅度 3—20% × 时长 5—300 s） | **全部 0/8** |
| **E7** | 反推测量不确定度需求（+10% 泄漏 300 s） | U 从 0.02 到 1.0 kPa **全部 8/8 检出**，但同时 **8/8 故障前误报** |
| **E8** | 真实灌水节拍校核（24/60/108 min 窗口） | 窗口内检出 7/8；停灌段误报 8/8 |

⚠️ **E6 与 E7 的门限口径不一致**（一组全 0、一组全 8，且 E7 全是误报），**不能互证**。这正是《项目方案批判性复核》指出的"双路径互证不成立"，也是门限扫描（P0-8）必须做的原因。

## 3.6 可辨识性（`results/identifiability.txt`）

- 单工况内 P1 只波动 **0.26%**，log-log 指数由噪声主导，实测拟合得 **−1.46（错）**
- 理论：斜率不确定度 ≈ `(σ_Q/Q)/√N / ln(P1_hi/P1_lo)`
- 压力跨度 1% → `n` 的不确定度 1.0—10（毫无意义）；**跨度 ≥20% 才降到 ≤0.05**
- 跨 80/120/160 kPa 三档（跨度约 100%）实测拟合 **n = 0.4755（正确）**

## L2　台架与水路

- **双支路清水台架**：A 被测 / B 健康扰动；A 支路串接供水首部 → P0 取压 → 可调受限段 R → P1 取压 → 流量计 → 正常负载 + 泄漏旁路 → 独立收集计量
- **严重度注入**：受限用可调节流阀；泄漏用旁路可调阀门 + 独立量筒（取样 18 秒，容量已校核）
- **水路要点**：短引压管 + 排气阀 + 向上坡度（水介质下**引压管积气是最大零点误差源**）
- **现状**：207 构件概念 CAD 已完成，**未加工未装配**

## L3　嵌入式软件

| 层级 | 现状 | 缺口 |
|---|---|---|
| 诊断内核 | `integer_diagnosis.c/.h` 380 行，整数实现，主机已验证 24 个边界向量 | 缺 CUSUM 分支的实证对照表 |

| 时间基准 | **无 RTC** | 重启后时间映射失效，实验数据与人工记录对不上 |

**里程碑**：S1 点灯串口 → S2 单通道采集 → S3 双通道+脉冲计数 → **S4 能写 SD 卡并读出来（能力分水岭）**

## L4　上位机与平台

- 桌面 V1.3（EXE，本机交付目录，不进源码仓库）；Web V1.2 **八页**（总览 / 支管监测 / 异常事件 / 设备链路 / 历史记录 / 设置 / 策略实验 / 试验台架）
- 数据链：串口服务 → 校验/去重/冲突回滚 → SQLite → ACK
- **四条语义边界**（必须守住）：
  1. 接收 ACK ≠ 人工已查看 ≠ 复测归档，三者各记时间
  2. 数据正常 ≠ 在线；离线时显示"无法判断 + 最近有效时刻"，**不能拿旧数据填成正常**
  3. 独立真值不由检测器输出生成
  4. 定位只到"支管编号—两测点包围区段—建议检查部位"
