# 第一部分　评审怎么看图（检索结论）

依据：[SciDraw 国自然科研绘图全指南（2026）](https://sci-draw.com/zh/blog/research-grant-illustration-guide)、[学者网：课题申报配图，密集不等于讲清楚](https://www.scholat.com/orgPost.html?id=12144)、[知乎：项目申请技术路线图怎么做](https://zhuanlan.zhihu.com/p/1992001555713508893)

## 1.1 两条硬规律

> **① 评审分给每份申请书的时间"以分钟计"，技术路线图是他翻到"研究方案"时看到的第一眼。**
> **② 文字可以略读，图不会被略过——图要么帮你把逻辑讲清，要么暴露"方案没想透"。**

## 1.2 技术路线图的正确画法：先想结构，再动手

**三步法**：

| 步骤 | 做什么 | 要点 |
|---|---|---|
| **第一步：纵向分阶段** | 按时间/逻辑切 3—4 个阶段 | 每阶段回答"解决什么、产出什么"；**阶段间必须有依赖链**（上阶段产出 = 下阶段输入） |
| **第二步：横向列任务** | 每阶段下挂 2—4 个具体任务 | 写"能落地的动词短语"，不写"开展相关研究"；**任务粒度对齐正文研究内容** |
| **第三步：标节点与成果** | 阶段交界处标里程碑（菱形为惯例）；右侧/下方放预期成果 | 评审顺图走一遍，应能复述出"每年干什么、验收什么" |

## 1.3 三个必须避免的错误

| 错误 | 表现 |
|---|---|
| **画成组织架构图** | 只有分类、没有流程 |
| **塞进全部细节** | 评审要骨架，不要说明书 |
| **配色超过四种** | 花哨等于不专业 |

## 1.4 其他规范

- **版式**：横版 16:9，从左到右的时间轴
- **同阶段同色**：颜色只用于区分阶段，不做装饰
- **箭头**：只表达依赖关系，不做装饰
- **图文一致**：图和正文对不上是常见扣分点

# 第二部分　项目现有可视化约定（从绘图脚本提取）

来源：`scripts/plot_diagnosis_review.py` 等脚本的实际设置。

## 2.1 字体与字号

```python
plt.rcParams.update({
    'font.sans-serif': ['Microsoft YaHei'],     # 中文字体
    'axes.unicode_minus': False,                # 正确显示负号
    'svg.fonttype': 'none',                     # SVG 保留可编辑文字
    'font.size': 13.5,
    'axes.labelsize': 14,
    'axes.titlesize': 16,
    'xtick.labelsize': 13.5, 'ytick.labelsize': 13.5,
    'legend.fontsize': 13.5,
    'axes.spines.top': False, 'axes.spines.right': False,   # 去掉上右边框
})
```

**关键约束（脚本内有断言）**：

```python
assert text.get_fontsize() >= 13          # 所有文字 ≥13pt
```

**主标题 18pt、副标题 13.5pt、脚注 13.5pt**，标题用 `weight='bold'`。

## 2.2 尺寸与输出

| 项 | 约定 |
|---|---|
| 典型画布 | `figsize=(8.5, height)` |
| 导出 dpi | **200** |
| 背景 | 白色 |
| 输出格式 | **同时出 PNG 与 SVG** |
| 网格 | `grid(alpha=.15)`，`set_axisbelow(True)` |

**为什么要 PNG + SVG 双出**：SVG 文字可编辑（投稿/改版方便），PNG 用于插入 Word 与灰度检查。

## 2.3 配色

| 变量 | 含义 | 色值 |
|---|---|---|
| `G` | 绿（正常/健康/参考） | 约 `#1b7f4b` |
| `O` | 橙（泄漏/告警） | 约 `#d95f02` |
| `M` | 灰（注释/次要） | 约 `#6b6b6b` |
| `B` | 蓝（参照线/边界） | 约 `#2b6cb0` |

**四种颜色，与"不超过四种"的规范一致。**

## 2.4 元素约定

| 元素 | 约定 |
|---|---|
| 参考曲线 | `lw=2.5` |
| 边界线 | `ls='--', lw=1.7` |
| 事件时刻 | `ls=':', lw=1.4` |
| 数据点 | `s=35—45`；"持续提示"用实心，"演示参照"用空心 `facecolor='white'` |
| 注释引线 | `arrowstyle='-'`（不带箭头，避免与流程箭头混淆） |
| 文字位置 | `fig.text(.04, .962, 标题)`、`.914` 副标题、`.045` 脚注 |

## 2.5 图注与来源可追溯（本项目特色）

每个图导出时附带 **series 清单**，写入 SVG 元数据：

```python
save(fig, 'range_and_measurement',
     '当前参数是否落在候选量程内，哪些误差需先解决？',
     series=[{'curve':'reference_dp','q':ref.tolist(),'dp_kpa':(...).tolist()},
             {'curve':'grid_flow','q':q.tolist(),
              'source':'simulation/hardware_results/range_grid.csv'}])
```

**⇒ 每个图都记录了"它回答什么问题"和"数据来自哪个文件"。这是本项目比多数申报书强的地方，必须保持。**

## 2.6 Word 插入的尺寸约束

| 项 | 要求 |
|---|---|
| 正文图宽 | 410 / 380 pt（两种） |
| 主要文字 | ≥9 pt（插入后） |
| 图注位置 | 与图同页 |
| 彩色图 | 灰度下仍可区分（需线型/标记区分，不能只靠颜色） |

| R2 | **E7 扩展到 U=5 kPa** | 当前 1 kPa 内全达标，曲线无拐点，需找到失效点 |

## 5.3 规格检查清单（每张图出图前逐项过）

```
□ 16:9 横版（或用图自身的合理比例）
□ 配色 ≤4 种
□ 中文字体 Microsoft YaHei，负号正常
□ 所有文字 ≥13pt（脚本断言）
□ grid(alpha=.15) + set_axisbelow(True)
□ 去上右边框
□ PNG + SVG 双出，dpi=200
□ 附 series 清单（回答什么问题 + 数据来源）
□ 图注与正文引用一一对应
□ 插入 Word 后主要文字 ≥9pt、图宽 410/380pt
□ 灰度下可区分（不能只靠颜色）
□ 箭头只表依赖，不做装饰
```

# 第六部分　结论

## 6.1 现状评价

| 维度 | 评价 |
|---|---|
| 图的数量 | ✅ 充足（38 张） |
| 绘图规范 | ✅ **规范且严格**（字号断言、双格式、series 溯源、灰度检查） |
| **技术路线图** | ❌ **缺失**——而这是评审看的第一眼 |
| 理论支撑图 | ❌ 缺（多模态原理、可辨识性） |
| 新仿真成图 | ❌ 缺（门限扫描、二维边界） |
| 图注体例 | ⚠️ 不统一 |

## 6.2 最该做的三件事

| # | 事项 | 理由 |
|---|---|---|
| **1** | **画技术路线图** | 评审翻到"研究方案"看的第一眼；目前完全缺失 |
| **2** | **把本次仿真的两张核心图做出来**（门限扫描、二维可检边界） | 这是项目最有说服力的数据，不图化等于白做 |
| **3** | **补多模态原理图** | 支撑"新意"的可视化证据，目前只有文字 |

## 6.3 一句话

> 本项目的绘图规范已经比多数申报书严格，**缺的不是规范，是"最关键的那几张图"**——尤其是评审第一眼就看的技术路线图，以及本次仿真产生的门限扫描与可检边界。
