# 软件与三维升级包使用说明

这次升级接通的是主机软件原型：压力时序适配 → 编译后的 C 诊断核心 → V2 协议回环 → SQLite → 本地网页。它没有接入 STM32、真实串口、LoRa 射频或阀门。网页回放、策略实验与三维模型均有明确来源，不能作为实物验收记录。

## 打开网站

直接打开 `deliverables/index.html` 即可查看离线回放。支管监测页包含趋势、窗口特征、三维台架入口和采集策略实验工具。异常事件页可以填写核查记录，历史页可以导出 CSV。浏览器记录属于演示工作区，不会把候选模式改成确认故障。

在当前电脑运行 `scripts/启动运行平台.ps1`，按终端地址打开 `http://127.0.0.1:8765`，再点击“连接本地后端”。选择场景后“新建会话”，按“推进30秒”逐批运行 C 核心并保存记录。旧会话保留在 SQLite，新建会话不覆盖它。关闭服务后重新启动，先显示只读历史，不自动恢复采样或把旧记录标为实时数据。

数据库位于 `tmp/platform_runtime/operations.sqlite`。请保留这个文件及浏览器本地核查记录；代码更新不需要删除数据库。本轮未迁移旧版 K/R 页面中的浏览器记录，原存储仍保留；可在设置页只读导出旧记录。新回放的核查记录使用独立存储名，不与旧算法快照混合。

本轮运行环境验证为 Python 3.10；其他版本须另验依赖兼容性。在其他电脑使用 Python 3.10，安装 `requirements-platform.txt` 中的依赖，并使 GCC 可从命令行运行。执行 `python scripts/run_platform.py`。升级包附带本机验收使用的 Windows 主机 C 程序及源文件摘要；相同源文件可直接复用，源码变更后会要求重新编译。这个程序不是 STM32 固件。三维网页是自包含文件，不需要另装 CAD 软件；重新生成模型才需要项目原有 OCCT 环境和对应技能。

## 网站各模块的用途

| 模块 | 可以做什么 | 记录的含义 |
|---|---|---|
| 运行总览 | 查看 P0、P1、Q₁₀、质量、候选与待处理事件 | 回放游标，不作节点实时新鲜度判断 |
| 支管监测 | 看趋势与特征，核对测点、三维结构和实验对照 | 缺测断线；短窗只是关注提示 |
| 异常事件 | 查看原始快照，追加查看、待复测、继续检查和人工归档 | 协议 ACK、人工查看和处置状态分开 |
| 设备与链路 | 核对计划设备和实际软件接入状态 | 主机回环入库不表示 LoRa 已成功传输 |
| 历史记录 | 分页查看采样，导出带来源和版本的记录 | 不把人工备注写回诊断字段 |
| 系统设置 | 查看冻结配置、拟合候选参照、演示控制请求 | 参照不自动切换，LED 是网页软件指示 |

人工归档须先记录已查看，并单独填写复测依据；当前测量质量不满足要求时保留待复测。归档只是结束人工工作项，独立参考测量仍需实验者落实。请求、软件收到、模拟执行和复位是四个独立动作，不自动依据候选诊断关阀。

## 算法与研究边界

当前 C 主线固定每秒输入一个端点；10 秒主窗使用11个计数端点和10个压力采样，连续5次越限形成候选。3秒短窗连续2次越限只提示关注。压力非有限、越界或时序错误不能以历史值补齐；计数复位后窗口重建。

离线网页使用27组新生成的 C 回放，包括3档模型压力噪声与9类场景。健康训练使用种子69001，回放使用70001。事件触发实验使用71001—71003的独立种子，1/2/5秒巡航间隔及全部相位，共432组。该策略运行在独立 Python 参考模型，压力只在请求时读取，脉冲计数每秒连续更新。它不是已经移植完成的休眠固件；压力读取次数不能换算成实测电量。

另有72组未见供压与负载特性的 C 参照挑战。不同负载特性会导致正常水路误报，因此增加多压力点健康标定是合理的延伸。参照拟合工具要求至少9组数据、3个压力档和20 kPa压力跨度，输出候选压力—流量曲线、阻力基准及残差。拟合残差是样本内结果，不等于独立验证；候选配置的健康批准标记始终为零，短窗标定仍须单独完成。导入数据不会覆盖当前运行参照。

## 三维结构

V1.1 模型沿用 A 支路 P0—受限元件—P1—Q—正常负载/泄漏分流及 B 共源健康切换支路。新增防溅板、过线开口、匹配安装孔，调整接头前的线缆包络。模型通过新增板与原构件的交集检查及 STEP 重开实体有效性检查，但没有做全装配公差、耐压、流量计安装要求或防护等级认证。

收集杯沿用约679mL几何内腔；20秒分次计量先要求独立实测安全液位有效容量不小于440mL。几何容量不是标定容量，模型没有解决长时自动排水。参数化模型与供货外形包络用于准备实验，不能直接交付加工。

## 复现与后续路线

执行顺序：`simulation/extend_platform_reference.py` → `scripts/build_system_upgrade.py` → `scripts/build_upgrade_bench.py` → `scripts/verify_platform_upgrade.py` → `scripts/verify_platform_browser.mjs`。浏览器检查使用当前电脑的 Node 和 Edge，截图保存在 `deliverables/软件升级验收预览`。只改网页时可用 `scripts/build_portal.py --operations-only` 复用冻结回放，不重新跑实验。

下一阶段先做传感器标定、清水台架装配与真实采集时序检查，再做串口与 LoRa 联调、跨供压和正常阀态对照。收集独立健康压力—流量参照后，才验证真实故障的主窗候选、短窗响应和事件触发策略。论文重点可以放在跨工况可辨识边界和采样策略的误报—延迟—读取次数权衡；能耗结论须另有平均电流和测量时长证据。申报书本轮保留原稿，等待真实实验确认后再同步成果表述。
