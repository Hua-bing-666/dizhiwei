## 1. 项目一句话定位

- **题目**：基于 LoRa 的南疆滴灌支管道早期故障诊断物联网原型系统。
- **应用场景**：南疆规模化棉田膜下滴灌，支管（不是滴灌带）这一层。
- **两类故障（本期只做这两类，不扩）**：
  1. 支管下游**等效泄漏**（接头漏、旁路跑水）；
  2. 测点区段内**等效过流受限**（被堵、被夹扁、阀门半关）。
- **明确不做**：单滴头堵塞定位、厘米级漏点定位、自动关阀、云平台、App、太阳能、多节点大规模组网、水质/施肥监测、作物长势。这些写进"后续扩展"，不写进本期交付。
- **"早期"怎么定义**：以独立参考流量相对同工况健康值偏离 **5% / 10% / 15%** 三个程度为标尺，记录"故障发生→本地首次持续正确提示→远端首次存储"三个时刻；15% 是本期实验参照，**不代表棉花减产阈值**，也不承诺提前几天预警。

## 2. 为什么是这个问题（背景要讲，但别铺太开）

- 南疆棉花膜下滴灌面积大，支管轮灌频繁，**轮灌切换 1–5 分钟一次、末端压力衰减 1–8 分钟**——这是天然的强干扰背景。
- 只看首部总流量，看不到是哪根支管出问题；人工下田覆膜地里逐段摸，又慢又依赖经验。
- 已有文献（仓库参考文献 [1]–[8]）证明：压力/流量法能做泄漏与堵塞识别，LoRa 在农田里能用，事件触发通信能省包。**但没人用南疆棉田真实轮灌数据回答"正常切换和故障到底怎么区分"这个问题**——这就是我们的空间。
- 政策依据：十五五规划"提升农业综合生产能力""强化农业科技和装备支撑"，节水灌溉方向对得上。

> **汇报时不要说的话**（材料里已经反复自我约束过）：
> - 不要说"替代人工巡检"——是辅助巡检，不是替代。
> - 不要说"省成本"——前期大概率比人工贵，定位是"风险对冲、避免一次大面积减产"。
> - 不要说"高精度定位漏点"——只到"支管编号—两测点包围的区段"，具体漏点靠人下去找。

## 3. 系统长什么样（一张图讲清楚）

```
棉田支管 Q(脉冲流量计) → 取压嘴A → 区段R(孔板+针阀) → 取压嘴B → 泄漏球阀 → 正常负载
                              ↓
                    GD32F103CBT6 节点（4–20mA 差压+干管参照、SGM58031、脉冲流量计、microSD）
                              ↓ E220 LoRa
                    USB-TTL 接收端 → 已有电脑 → SQLite → 本地 Web 六模块
                              ↓
              巡检人员：总览 / 支管监测 / 异常事件 / 设备链路 / 历史记录 / 设置
              闭环：告警 → 人工查看 → 现场处置 → 同工况复测 → 归档
```

- **双支路清水台架**：A 支路挂监测节点（被测），B 支路模拟"隔壁另一组轮灌在开关"，用来复现轮灌扰动。
- **预算**：启动约 **2409 元**（BOM v2.2 下限，明细见 `docs/硬件选型与BOM冻结_v2.md`；上限 5018 元）。
- **执行期**：2027 年 3 月–2028 年 2 月；**真正能进棉田的窗口只有 2027 年 4–9 月一个灌溉季**。

## 5. 两个核心科学问题（论文就从这两个里面选一个）

### 问题 A：双压力–流量联合观测，在轮灌干扰下到底比单流量阈值好多少？
- 现状里我们**已经发现反例**：
  - 高压力噪声（σ=10 kPa）下，K/R 方法泄漏只识别出 1/20，反而不如固定流量阈值的 20/20；
  - 未知正常负载增大和泄漏**长得一模一样**；
  - P0 传感器零点飘一点，就会被误判成"受限"。
- 所以论文 A 的真问题是：**在多大测量误差、多大供压波动范围内，双测点方法才开始赢单流量基线？** 赢多少、在什么条件下输——把这条"适用边界曲线"画出来，就是贡献。

### 问题 B：同样的本地判断，事件上报比周期上报到底省多少、又慢多少？
- 要在**同一段本地检测轨迹**上，公平对比快周期 / 慢周期 / 原始事件 / 滤波限频事件四种策略。
- 指标：远端告警延迟 P50/P95、期内送达率、重传率、缓存溢出缺口、**实测整机电流**（不能用发了几帧代替）。
- 这条路需要真 LoRa、真电流计，工作量大，但故事完整。

> **主线选 A，B 作为备选/第二作者内容**。理由：A 主要靠台架就能做，不依赖田块；B 必须有真链路和功耗实测，不确定性更大。

## 7. 汇报时要**重点讲透**的 6 个点（老师大概率会追着问）

1. **"早期"到底早多少？**
   - 现行仿真口径：**80 s 注入窗内**，泄漏 **+2%** 40/40 检出、受限 **+50%** 40/40 检出（h\*=26 为仿真基准，未建模各通道独立传感器噪声）。**这是合成数据里的边界，不是棉田里的数**。真正要报的是"到达演示参照档偏离前的有效早期比例"，并同时报故障前误报次数（次/小时）。
2. **单只差压变送器压得住 +2% 边界信号吗？**
   - 0—40 kPa 档 / ±0.5%FS ⇒ **U ≤ 0.20 kPa**，在 +2% 边界幅度下需求 U ≤ 2.0 kPa，设计工况（U ≈ 0.20 kPa）余量 10 倍。**这个数能不能在实物上复现，是整个项目成败的第一关**，必须在 G1 用参考仪表实测回答，不能靠选型表。
3. **轮灌切换和泄漏到底怎么分？**
   - 我们现在的答案是"切换期间暂停分类、等工况稳定再判"——但这会丢掉切换那几十秒里的故障。这 12 次"切换期间故障"实验就是专门测这个代价的。
4. **2000 块钱真够吗？**
   - BOM v2.2 总额 **2409—5018 元**（含天线/RTC/防反接/高边开关/PCB/孔板/电平整形等八项漏项），专项额度 6300 元、余量 ≥20%。**前提仍是借用连续水源和参考压力表/流量计**；如果水要接自来水、参考仪表要自己买，额度就紧了。这一条要请老师帮忙落实借用渠道。
5. **你一个大二通信的，GD32 固件写得出来吗？**
   - 诚实答：现在只会焊接，C/定时器/ADC/脉冲计数都还在学。2026.11–2027.2 是预留的学习窗口。**如果到 2027.3 还写不出有线采集，需要老师帮忙安排嵌入式方向的队友或研究生带一下**。
6. **和已经发表的那堆灌溉 WSN 论文比，新在哪？**
   - 不在"用了 LoRa"，也不在"加了个压力传感器"。**在两个地方**：①把南疆轮灌扰动当作**一等公民**写进实验设计，专门做"切换期间故障"这一组别人没做的对照；②用双压力点而不是单点，并且**报告它什么时候反而更差**（σ=10 kPa 那个反例）。诚实报告边界，是方法贡献，不是 weakness。
